# UI 交互与视觉

整理日期：2026-09-15

工作台的单位是**智能体和群**，不是一次性对话。侧边栏用来认人，聊天区用来办事，头像用来表示它活着、在干什么。没有云电脑。删除智能体/解散群只有人能做。

本文对齐平台能核实的交互（侧边栏右键删除、点标题打开资料、设置不在齿轮里），以及你们已经落地的视觉 token。不确定的平台菜单不编。

相关：`群聊点名.md`、`协作投递.md`、`对话线与群边界.md`、`群动作与提示词.md`、`web/src/components/LivingAvatar.tsx`。

---

## 1. 三块布局

```
┌──────────┬──────────────────────────┬─────────────┐
│ 侧边栏    │ 聊天                      │ 资料（可关） │
│ 智能体    │ 标题：名字 + 活头像        │ 名字/职责    │
│ 群        │ 时间线                    │ 形状/颜色    │
│ 主人账号  │ 输入条                    │ 群则成员列表 │
└──────────┴──────────────────────────┴─────────────┘
```

- 默认打开上一次的频道。没有选中时显示欢迎空态，不要空白桌面。
- 资料页不是全局设置。点聊天标题的名字打开/关闭（平台是点名字或 Cmd+Shift+I）。
- 全局设置：侧边栏底部账号行，或 Cmd+,。不要在标题栏放齿轮当全局设置。
- 没有停止按钮。停靠输入框打「停」。

宽度：侧边栏约 240–280，可拖；窄到约 90 只留头像。资料页约 320。聊天区吃剩余宽度。

## 2. 侧边栏

两段，不要混成一个「会话列表」：

1. **智能体** — 每个是 1:1  
2. **群** — 最多 6 人，复合头像或叠脸  

行内容：活头像、名字、一行预览；群头像直接叠放成员脸，不放白色方卡，也不加“群”字标签和右侧时间。未读是行右的数字徽标（迷你模式挪到头像右上角），群和 1:1 都算；正在看的那条不算。已读位置存本机 `localStorage['agentbot.readMarks']`，重启不丢；第一次打开没有记录时当作全部已读。正在干活时头像进入 `working`，不要再靠文字「正在输入」，也不要再叠脉冲圈或忙碌点。头像右下角的状态点只表示暂停 / 消息没处理成功 / 消息等处理，和未读徽标分开两个角。

### 点击

| 操作 | 结果 |
| --- | --- |
| 点一行 | 打开该 1:1 或该群；未读清零 |
| 点底部账号 | 打开全局设置（主题、语言、名字） |
| 点 `+` | 建智能体或建群，一张表单，不要两个隐藏入口 |
| 右键智能体 | 编辑资料 / 删除（删除要二次确认，人和对话一起没） |
| 右键群 | 重命名 / 解散（同样确认） |

模型没有删除工具。界面上删除只出现在人的右键菜单里。

搜索过滤名字，不搜索全文。没有匹配给空态一句，不要转圈。

常用智能体可拖到侧栏顶部的置顶区；尚无置顶项且开始拖动普通智能体时才展开虚线投放区，平时不占空间。已有置顶项时不再出现虚线区，直接在置顶卡之间显示插入位置。拖动预览只显示头像和昵称，不把整张会话卡带走。可连续置顶多个智能体；置顶卡之间可拖动排序，放到普通会话列表即取消置顶，拖动时分别提示插入位置与取消置顶目标，落位后已有置顶卡平滑移位。置顶卡默认透明，鼠标悬停才显示背景；卡内只显示头像、名字及可选的独立短头衔（title），不显示职责或描述。也可从右键菜单置顶/取消置顶。置顶顺序保存在本机，搜索仍覆盖所有智能体和群。置顶项不重复出现在普通会话列表中。默认头像按智能体身份分配几何形状和颜色，显式自定义头像/颜色优先。普通智能体和群不分组，按最近活动混排；普通会话列表的自定义拖拽排序以后再做。

## 3. 1:1 聊天

时间线只有你和这一个智能体。群回合若出现在这条线上，用房间标签标出来（「在 白泽联调」），不要画成另一条私聊气泡。

同事给它的短信：中间一条淡色 correspondence「某某 → 某某」，点开才看全文。主人在 1:1 里能看见传话，但不是群时间线。

消息：

- 你：右侧，使用 `--ai-user-bubble` 轻强调底。
- 智能体：左侧，使用统一的低对比卡片底；名字沿用智能体身份色，头像形状与颜色保持一致。
- 群消息：成员回复靠左并展示身份；主人发送靠右，不重复展示头像和名字。消息卡片共用同一套正文排版，不为每个成员另造气泡风格。
- 同一人连续发送的纯文本消息各自保留气泡，间距收紧；首条与末条靠发言者一侧的接缝圆角缩小，中间条两端都缩小。后续消息不重复头像、姓名和时间；工具调用、错误或换人会断开这一视觉连接。
- 工具过程：折叠卡片，默认收起，不跟正文抢。

进行中：头像 `thinking`/`working` 表示状态，旁边只留一行名字与动作。模型草稿先经过出口校验，工具过程不泄露为正文；通过校验并落盘后，最新回复逐字显现。群成员用活头像表示工作状态；回复落入群时间线时从下方轻柔上浮，主人的消息短促弹入右侧。

选项卡、密钥框、附件只出现在 1:1。卡片是最后一条，选完才继续。密钥不明文进时间线。

输入条：多行、Enter 发送、Shift+Enter 换行。没有停止键。打「停 / 取消 / 先别做了」即停止令。

## 4. 群聊天

时间线 = 该群公开说过的话。不要把任何人的私聊画进来。

每条：说话人的活头像 + 名字 + 正文。主人一条、智能体各用自己的颜色/形状。`@名字` 高亮；点名字或 `@` 可插入 `@该人`。

未读：不在当前群时，侧边栏该行红点。打开即清。

成员开口/沉默不要在发送按钮旁出「3 开口 / 1 沉默」。要看状态：侧边栏各人头像，或资料页成员列表上的小状态。

输入条和 1:1 同一套。`@` 弹出在场成员（含 id 展示可先不做）。`@everyone` 给一项。群里不能发选项卡/附件/密钥；点这些入口时 toast：「群里只有文字，改口或私发」。

群头：名字、人数（n/6）、点开资料页看成员。加人减人在资料页，不在输入条。满 6 人禁用添加。

## 5. 资料页

点标题打开。关：页头 X，或再点一次标题。

智能体：预览活头像、名字、头衔（title）、简介（description）、职责（instructions）、形状、颜色、通知开关。四个文本字段分开编辑，各存各的（E5.1）。头像可以上传图片（落数据目录的 `avatars/`，界面读 `GET /api/agents/:id/avatar`）或清除——清除是真的删文件并置空，不是「没改」。自定义图盖住默认脸。没有删除按钮。

群：名字、成员列表（头像+名字+职责一句）、添加（已在群里的除外，总数 ≤6）、移出（人操作）。

平台资料页还有例程、频道、电脑预览。你们不做云电脑；例程/频道没做之前不要画空壳电脑窗。

## 6. 建与删

建智能体：名字必填，职责、颜色、形状可选。创建后立刻打开它的 1:1。

建群：名字、勾选 1–6 个已有智能体。创建后打开该群。

删：右键 → 确认文案写清「对话一起删除，不可恢复」。共用层记忆不在这张确认里假装会擦掉。

## 7. 视觉风格

**具体数值（颜色、字号、圆角、层级、阴影）一律以 [主题与CSS.md](主题与CSS.md) 和 `web/src/styles/01-tokens.css` 为准**，本节只讲取向，不再重复写数，免得两份文档各说各话：

- 令牌与主题：主题与CSS.md §1（两套主题、默认浅色、`data-theme` + `color-scheme`）。
- 字号 / 圆角 / 时长刻度：主题与CSS.md §2.1、§2.2；字重只用 400 / 500 / 600（名字 600）。
- 层级与布局尺寸（侧栏宽、行高、阅读列）：主题与CSS.md §2.4；气泡与消息头像（28）：§4；断点：§6。

**气质：** 沿用现有米色/古金浅色与深色主题，不另起品牌色。页面靠稳定的背景层级、细边框和克制阴影建立秩序，少装饰。侧边栏与聊天区有轻微层级差，强调色只用于选中、焦点与主要动作。

**层次：** 背景层级按令牌走（聊天底、侧栏、卡片 / 菜单、输入框各有语义令牌），边框细，不要厚描边。

**字：** 界面 `--sans`；代码 `--mono`。聊天正文统一 `--fs-md`，主人与智能体同一套字号行高。次要信息用 `--text-secondary`，不要用透明度乱叠。

**圆角：** 用 `--r-*` 令牌，头像随形状，不要一律切圆。

**消息卡片：** 主人与智能体都使用同一套圆角与内边距；主人用浅强调底，智能体用中性表面底。群里成员共享这套卡片，只用头像和名字颜色区分发言人，不使用高饱和大彩泡。

**图标：** 线性、细、少，不用 emoji 当图标。能用活头像表示的状态不要再叠一个绿点+三个点+「正在输入」。

亮/暗跟随 `data-theme`。设置里可选浅色 / 深色 / 跟随系统，没选过默认浅色（以 `theme.ts` 与主题与CSS.md §1 为准）。

## 8. 动效原则

少、短、有含义。装饰性循环动画只留给活头像。

**时长、曲线与允许循环的动画清单以主题与CSS.md §2.2、§8 为准**，这里不再列数值。取向：

- 进出场用现成 `usePresence`，卸载前播完再卸；折叠用 `0fr → 1fr`，不要写死 `max-height`。
- 切频道：`.swap` 短淡入，不要左右滑一整页。
- 思考 / 忙碌：头像 `thinking` 表情加输入条上方一行「名字 正在…」，不做假气泡、不要骨架屏闪整页。
- `prefers-reduced-motion`：`08-animations.css` 已把动画打到近 0；活头像冻结为静态一帧。

不要：弹性乱跳、消息从底飞入一长串、工具卡片每步闪一次、群里每人开口全页抖。

## 9. 活头像（状态就是脸）

默认标 = 形状 + 颜色 + 双瞳，不是一张 PNG。自定义 `avatar.png` 盖住它，状态改走侧边小徽章（未读、忙）。

形状/颜色枚举见 `web/src/components/LivingAvatar.tsx` 的 `AVATAR_SHAPES` / `AVATAR_COLORS`。状态：

| 状态 | 脸 | 侧边栏 |
| --- | --- | --- |
| idle | 慢呼吸、偶眨眼 | 静止名单 |
| thinking | 眼睛左右扫 | 可无文字 |
| working | 节奏加快 | 脸在动即「在干活」 |
| waiting | 抬眼 | 等人（选项卡、密钥） |
| blocked | 停住、略歪 | 需要人 |
| done | 落下来一下再 idle | |

群复合头像：叠 2–3 个成员脸 + 余数。群自己不呼吸；成员 working 时对应那一小脸动。

实现用现有 `LivingAvatar.tsx` / `demo.html`，不要再为每个人画死 SVG 角色（白泽/机柜可留作自定义图，不是默认标）。

悬停头像：可出一句当前动作（「在查 159」）。没有动作就不出。

## 10. 群里的顺序怎么表现

不给「第 1 发言人」控件。

被 `@` 的人串行开口：时间线上自然先后出现，后一条可以接前一条。没 `@` 的人并行：可能几乎同时冒出来，不要用动画强行排成队列，以免看起来像在对楼。

某人还在跑：它的头像 `working`，时间线先不要占一句「正在回复」。开口后再插入气泡。沉默：什么也不插。

## 11. 反馈与空态

- 发送：消息马上出现在时间线（乐观），失败再标红可重试。  
- 空 1:1：一句职责 + 「直接打字」。  
- 空群：成员头像一排 + 「@ 谁，或说你们好」。  
- 错误：行内，不要模态挡输入。  
- Toast 只用于「群里不能发附件」这类瞬时规则。  

通知：未读红点始终在；系统通知跟随资料页开关。不要靠浏览器标题闪烁当主状态。

## 13. 现在有的 / 建议补的

**已有：** 暗色 token、亮色主题、侧边栏 1:1/群、右键删、资料抽屉、活头像组件、进出场 `usePresence`、思考点、correspondence、选项卡/密钥卡片、成员面板、右侧面板的「工作」标签（E4.7：目标/状态/进展/等待对象/下一步/交付物，步骤按需展开）。

**建议先补：**

1. 默认脸真正接到侧边栏/时间线状态（idle/thinking/working），替换按名字画死的角色 SVG。  
2. 群时间线与 1:1 视觉分开：群用名字+头像流，1:1 才是你/它两列。  
3. 输入条去掉停止键（若还在）；停靠打字。  
4. 群输入 `@` 菜单；满 6 人禁用拉人。  
5. 资料页拆 title / 职责；形状+颜色选择器（复用 `LivingAvatar` 的形状/颜色枚举）。  
6. 「面向全群的招呼」若采用全员点头：UI 仍并行冒泡，不要做成排队打字机。

**不要做：** 云电脑预览、模型可点的删除、把私聊气泡渲染进群、在发送结果里展示开口计数。
