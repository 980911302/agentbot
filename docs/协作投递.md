# 协作投递

整理日期：2026-09-15

人跟智能体说话、智能体跟同事说话、智能体在群里说话，是三条不同的路。混在一起就会把「发短信」做成「同步导演」。

本文写平台实际怎么跑，以及 AgentBot 该怎么改。不写云电脑。停止砍树见 `架构设计.md` §0.3、§7，提示词分层见 `提示词.md`。

---

## 1. 两个出口，不要第三种

| 工具 | 发给谁 | 这一轮等不等回 |
| --- | --- | --- |
| `SendToUser` | 主人；若当前是群回合，默认进这个群 | 文本丢出去就继续；`end_turn=true` 才结束本轮 |
| `SendToAgent` | 一个同事，或自己所在的一个群 | **贴出去立刻返回**。对方的话是之后的新回合 |

没有 `say` / `stay_silent` / `post_to_room` 给模型用。

群里正在回合时：开口用 `SendToUser`。对主人说私话：同一工具加 `to:"dm"`。**禁止**再 `SendToAgent` 当前这个群——那会把整组重新叫醒。

`SendToAgent` 像发短信，不是 `Task`。收件人不是发送方任务树上的子工人。停发送方，不等于停刚喊到的同事。

受控群流程（见 `docs/群流程与行动权.md`）的正式交接不走普通 `SendToAgent`。平台签发带 HMAC 的 `replyRoute`，收件人仍是独立新回合，立刻返回；该回合可以用 `SendToUser(to:"room")` 把候选行动交回原流程。没有这条路由，独立私聊不能往任意群发。

## 2. 平台实际怎么走

### 2.1 私发同事

```
发送方本轮
  SendToAgent({ target_id: 同事id, message, images? })
       │
       ├─ 校验：不是自己、人还在、传话深度未到顶
       ├─ 写入收件箱（1:1）
       ├─ 主人在双方的对话里能看见这条传话
       └─ 工具立刻返回：「已投递给某某」
              │
              │  （本轮继续干活或结束，不空等）
              ▼
收件方之后被叫醒（新回合，线索 [agent]）
  简报：同事来信
  有实质才回：再 SendToAgent 回去
  要让主人知道的新结果：另 SendToUser
  纯「收到」不回
```

发送方**拿不到**对方这轮说了什么。回信以后作为一条新的入站消息，再开一轮。

### 2.2 发到自己所在的群（人不在该群回合里，或要从别的群/私聊喊一嗓子）

```
发送方本轮
  SendToAgent({ target_id: 群id, message })
       │
       ├─ 校验：发送方是成员；不是「当前正在回合的那个群」
       ├─ 群时间线追加一条（发送方身份）
       ├─ 每个其他成员：对话线记一条 + 收件箱入队（kind=room）
       └─ 工具立刻返回：「已发到某某群」
              │
              ▼
每个成员稍后各自开一轮群回合（仅 `open` 模式）
  带房间标签 / 群简报
  想开口：SendToUser(to:"room")
  不想开口：整轮不调 SendToUser
  若房间已是 `managed`：时间线仍写入，但不扇出全员；由流程授权唤醒当前行动者
```

发送方**不要**等待「谁开口 / 谁沉默」。不要在工具结果里写「3 人进入回合：2 开口 / 1 沉默」。

成员醒过来，等价于「群里出现了一条新消息」。和主人在群里打字后的扇出是同一套**入队 + 稍后回合**，只是工具调用必须先返回。

### 2.3 已经在某个群回合里开口

这不是投递，是本轮出口：

```
群回合进行中
  SendToUser({ type: "text", content, to: "room" }) → 进当前群时间线（受控流程则提交候选行动）
  SendToUser({ type: "text", content, to: "dm" }) → 只进主人与自己的 1:1
  整轮 0 次 SendToUser                      → 合法沉默
  省略 to                                    → 拒绝，DESTINATION_REQUIRED
```

正文里的 `@名字` / `@everyone` 由运行时解析，把被点到的人**再入队**一次（受每轮次数上限约束）。仍然是入队，不是发送方同步把他们跑完。

### 2.4 主人在群里打字

和 2.2 落盘形状相同：时间线一条 + 全体成员入队。调度可以分波（点名先说、旁观并行、再 @ 再跑），但这是**运行时自己的事**，不挡任何人的工具返回。HTTP / `SendToAgent` 都先回 202 / 「已发送」。

## 3. 数据怎么落

四种记录，不要挤成一种：

| 记在哪 | 是什么 | 谁看见 |
| --- | --- | --- |
| 智能体自己的对话线 | 私聊原文 + 自己参与过的群回合 | 该智能体的 1:1 界面；模型上下文 |
| 群时间线 | 这个群公开说过的话 | 群界面；进群后的成员**看不到**入群前的 |
| 收件箱 | 尚未变成回合的投递 | 运行时；不是给模型当历史读的 |
| 传话归档 correspondence | 1:1 短信副本 | 主人在双方聊天里看见的那条「某某 → 某某」 |

1:1 信：

```
{
  id, kind: "message",
  fromAgentId, toAgentId, fromName,
  text, images?,
  depth,                 // 传话链深度，到顶把结论给主人
  priority?,             // 仅 1:1：插到对方队列前面；不打断对方正在跟主人的对话
  correlationId?,        // 可选，便于界面串起来；不要用来 stop 传播
  createdAt
}
```

群投递（成员收件箱）：

```
{
  id, kind: "room",
  toAgentId,
  text,
  room: { roomId, roomName, roundId, speaker, summoned, everyone, stopRequested },
  priority: false,       // 群不能紧急插队
  createdAt
}
```

`roundId`：主人或某次 `SendToAgent` 发群产生的那一条公开消息，下游成员的回合都挂这个 id。方便晚到的人补看「这一轮已经有人说过」。

## 4. 叫醒（运行时，不是模型）

投递和执行必须分开。

```
enqueue(item)
  → 调度器看见该 agent 有可领取的信
  → 该 agent 空闲则 process()
  → 忙则等它本轮收尾再领

process()
  1. 领取（租约 + 次数上限）
  2. kind=stop 先处理
  3. kind=room  一封信一个群回合（不要和 1:1 合成）
  4. kind=message 一封信一个 1:1 回合（不要多封合成）
  5. 成功 ack / 失败有限重试 / 忙则归还
```

**一封信一个回合。** 不要 `composeLetters` 把 A、B 两个人的话压成一条再跑模型——来源会糊，简报只能写一个 `fromName`。

工具结果固定短句，便于前缀稳定：

- 1:1：`已投递给「{name}」；发出去就结束，回复是之后的新回合。`
- 群：`已发到「{roomName}」。`

不要把开口人数、排队名单写进工具结果。那些走群事件 / SSE，给界面用。

## 5. 和任务树的关系（这里最容易做错）

| 动作 | 是不是发送方的子任务 | 发送方停了会怎样 |
| --- | --- | --- |
| `Task` / 执行器工人 | 是 | 沿树取消 |
| `SendToAgent` 1:1 | **不是** | 对方该醒还醒；已在跑的那轮按对方自己的停令 |
| `SendToAgent` 发群 | **不是** | 信已经在时间线上；成员自己的回合自己管 |
| 当前群里 `SendToUser` | 本轮出口 | 只影响本轮还没发出去的话 |

AgentBot 现在的 `registerChild` 把 1:1 收件人挂上发送方的树，停发送方会去停收件人。拿掉。

`correlationId` 可以留给界面「这是哪次传话」，不要拿它做 `completeChild` / 停止扇出。

深度上限仍然要：`depth >= max` 时工具报错「把结论说给主人」，防止两个人无限对打。这是防环，不是父子任务。

## 6. 群调度（可以留，但别堵工具）

用户在群里说话、或 `SendToAgent` 往群里贴了一条之后，运行时可以对**已入队的成员**分波执行：

1. 被点名的，串行（后者能看见前者已经公开的话）
2. 在场未点名的，并行（互相看不见，但看得见第 1 波）
3. 同事发言里新的 `@`，再串行，每人每 `roundId` 有次数上限

这是队列消费者的策略，不是 `SendToAgent.execute` 的返回路径。

`SendToAgent` 发群的正确实现：

```
resolve 群（必须是成员）
若 target == 当前 room.roomId → 报错：用 SendToUser
append 群时间线
for 其他成员:
    记入该成员对话线
    inbox.enqueue(kind=room)
return 「已发到「{name}」。」     // 这里就结束
// 调度器稍后 fan-out，发送方这轮已经拿回工具结果
```

当前群里成员用 `SendToUser` 开口：只 `append` 时间线 + 解析 `@` 入队，**不要**再走一遍「全体扇出」。

忙的成员：信进收件箱，空下来再跑。不要静默丢信。

## 7. 解析 target

`target_id` 只认 **id**（同事 id 或群 id）。名字仅作回退，且必须消歧：

1. 先精确匹配同事 id，再精确匹配群 id。
2. 再按**自己认识的同事名字**、**自己所在的群名**匹配。
3. 两个都命中或命中多个 → 报错，列出 id，让模型改用 id。
4. 群必须 `memberIds.includes(callerId)`，否则「你不在这个群」。
5. 不要发给自己。

简报里点名同事时带上 id，模型就少走名字回退。

`priority=true` 只对 1:1 有效：插到对方收件箱前面。不打断对方正在跟主人说的那一轮。群投递忽略 priority。

`images`：1:1 应能带（和平台一样，收件人真的看见）。群忽略或明确报错「群里只有纯文本」。现在「任何 images 都抛错」过严。

## 8. 提示词（只写表现，不写队列）

基座里三句就够：

```
叫同事或往自己所在的群贴一条：SendToAgent（按 id）。发出去不等回。
当前群里开口：SendToUser。对主人说私话加 to:"dm"。
不要把刚发过的群再 SendToAgent 一遍。停你自己的活，不会自动停同事。
```

1:1 简报用现有 `buildAgentBrief`。群简报用 `ROOM_SKILL`。不要把 `viaAgent` 塞进群简报——1:1 不是群回合。

---

## 9. 界面

- 主人打开某个智能体：看见自己跟它的私聊，以及它参与过的群回合（带房间标签）。
- 1:1 传话：在双方的聊天里各有一条可见的 correspondence（某某 → 某某），不要只进收件箱主人看不见。
- 群：只渲染群时间线。成员各自是否已跑、是否沉默，用事件，不要用发送方的工具返回值。
- 没有「删除同事 / 解散群」的模型工具；主人在侧边栏做。

---

## 10. AgentBot 对照（现在 → 应改）

| 现在 | 应改 |
| --- | --- |
| `dispatch` 群路径 `await postToRoom`，等三波，返回开口/沉默人数 | 只写时间线 + 入队，立刻返回「已发到某群」 |
| 1:1 `registerChild`，停发送方停收件人 | 不入树；`correlationId` 仅归档 |
| `composeLetters` 多封合成一轮 | 一封信一个回合 |
| `images` 一律抛错 | 1:1 收下；群拒或忽略 |
| resolve 先名字撞同事再撞群，且不先滤成员 | 先 id，再「自己的同事 / 自己所在的群」，歧义报错 |
| 群简报里的 `viaAgent` | 删；1:1 只走 `buildAgentBrief` |
| 工具说明写「立刻返回」 | 与实现一致（改实现，不改口径去迁就同步导演） |

用户在群里打字的三波调度可以留，只要它发生在调度器里，不发生在 `SendToAgent` 的 await 里。

---

## 11. 完成标准

1. `SendToAgent` 到同事：入队后 **10ms 级**返回；单测在收件人 `process` 之前就能读到工具结果。
2. `SendToAgent` 到群：返回句不含开口/沉默数字；群时间线已有发送方那一条；其他成员收件箱各有一条 `kind=room`。
3. 当前群再 `SendToAgent` 同一 `roomId`：抛错，提示用 `SendToUser`。
4. 发送方被停：收件人已入队的 1:1 / 群信仍在，不会被 `completeChild` 取消。
5. 两封来自不同人的 1:1：两次 `runTurn`，两次不同的 `fromName` 简报。
6. 非成员 `SendToAgent` 某群：失败，时间线无新行。
7. 同名同事与群：不发送，返回两个 id。

单测只断言落盘和返回句，不要真跑模型等整组说完。
