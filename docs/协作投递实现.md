# 协作投递实现

依据根目录 [协作投递.md](../协作投递.md)，2026-09-13 更新。

## 边界

- `SendToAgent`：同事 ID / 所在群 ID。只校验、写入、入队，返回固定短句，不调用或等待收件模型。名字回退必须消歧；非成员失败时不落消息。
- `SendToUser`：当前群即时落公开消息并解析 @ 入队；`to:"dm"` 私发主人；无出口是合法沉默。回合结束不重复发布已经公开的文字，私聊插话后的群续跑也保留此出口。
- `InboxProcessor`：一次领取一封，逐封简报、执行、确认。忙则归还，失败有限重试，检查点继续防止盲目重放副作用。
- `InboxScheduler`：只管到期与空闲唤醒。取消发送者不撤销已受理消息；同事信不进入发送者的任务树，真正 Task 工人的取消机制保留。
- `roundId` 关联群里同一条初始公开消息，与发送者的停止树无关。成员投递的运行独立；同一成员的 @ 配额计入已确认投递并持久保存，重启不能重置为零。

HTTP 群入口在时间线和成员收件箱写完后才回 202；回执不是成员完成证明。进程内 `postToRoom` 兼容入口保留原三波策略，用于已有内部调用/测试；HTTP 与模型工具均不走该等待路径。当前普通队列消费者按成员空闲时机唤醒，不承诺点名成员严格串行。

## 交流语义

投递协议只负责送达，不把消息定义成任务。`SendToAgent` 的正文可以是问候、问题、信息或明确请求；指定原话须按原意发送，不能为了让智能体“显得在做事”而改造成任务。

1:1 收件方的独立新回合先按来信语义处理：问候自然回一句，问题直接回答，明确执行请求才开始工作。短确认在双方都收到后停止；不把每条同事消息转述给主人，也不因为对方有工程师身份就翻出旧项目、主动派工或附加计划。

群聊按 [群聊点名](../群聊点名.md) 的规则单独处理：在场成员都有回合；被 `@` 的人必须按原意回应。消息意图是面向全群的社交交流时，每位成员各回复一条短消息后结束，回复不得点名或引出工作。其他未被点名者只有同时满足“内容实质、别人没说过、归自己负责”时才开口。保留单轮发言与再次 `@` 的叫醒上限。

## 图片与身份

1:1 的图片引用贯穿工具参数、InboxItem、correspondence、Message、上下文与兼容 API 的 image_url 内容块；群拒绝图片。最多 4 张，每个 URL 最多 2048 字符，说明最多 300 字符，仅接受无用户名密码的 HTTP(S) URL。暂不支持直接传本地路径或 base64。往来详情可展开图片。

每张图预留 4096 个上下文预算单位，随近期历史、每次请求窗口一起裁剪；这不是实际计费或供应商识图 token 上限。必须选择支持图片输入的供应商/模型，不能保证所有 OpenAI-compatible 模型都支持视觉。

协议格式核对依据：[官方图片输入文档](https://developers.openai.com/api/docs/guides/images-vision)。本次未调用真实模型 API，流式和非流式图片请求均通过本机 mock HTTP 验证。

真实 sender 与模型 role 分离，UI 来源规则见 [消息身份与智能体往来](消息身份与智能体往来.md)。新增/重新入群时间限制旧群投递及回合简报；旧数据没有加入时间时只能保守以建群时间兼容，不会猜测历史成员变更。

## 验收与未承诺事项

`test/collaboration-delivery.test.ts` 覆盖发送先返回、发送者取消、群入队形状、当前群防重复、权限/同名消歧、深度限制、即时公开、不重复扇出、持久 @ 配额、重新入群、图片完整链路与参数限制。逐封来信及 HTTP 幂等另由 delivery/chat-architecture 测试覆盖，群续跑由 module-boundaries 测试覆盖。

- “立即返回”指不等待模型，仍需等待本机落盘；不承诺所有磁盘负载下严格小于 10ms。
- 跨时间线、成员经历、多个收件箱和往来档案尚不是单个事务；进程在中间退出仍可能造成部分投递。已受理的收件箱项可恢复，不能将工具报错理解为所有写入都没有发生，也不能盲目重发。
- 群配额只存小型计数，不保留正文副本；当前随 Inbox 状态持久保存。历史消息/档案仍全量加载，大规模存储索引与配额历史归档不在此次改造范围。
- 不重写已有真实聊天或旧停止树，不自动猜测过去错误的发送者；本次不增加用量统计。
