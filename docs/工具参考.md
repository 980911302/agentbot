# AgentBot 当前工具参考

更新：2026-09-15。依据 `src/server/tools.ts`、`src/server/runtime.ts`、`src/tools/limits.ts` 与 `src/tools/builtin/manage-room-flow.ts`。本文记录本项目实际实现，不把外部平台的工具目录当作已上线能力。逐工具限额及测试见 [工具边界审计](工具边界审计.md)。受控群流程见 [群流程与行动权](群流程与行动权.md)。

装配完整且联网开启时，当前工具定义共 25 个（原 24 个加 `ManageRoomFlow`）。具体智能体可用项由 toolNames 过滤，联网关闭时不装 WebSearch/WebFetch。运行时目录可从 `GET /api/health` 获取；该目录表示全局工具定义，不代表每位同事都有同样的授权。新同事默认拿到全部已装配工具。

## 1. 当前工具表

`*` 表示必填；参数的最终契约以源码 schema 和执行校验为准。

| 工具 | 主要参数 | 当前行为 |
| --- | --- | --- |
| SendToUser | type*、content、url、to、end_turn、delivery_refs、widget、secret | 文本、工作区文件交付、选项卡、密钥框；群必须显式 to；带 replyRoute 时提交流程候选行动 |
| Read | path*、offset、limit、column | 流式分段读文本；默认 200 行，最多 500 行/12000 字符；offset 为负时是从末尾起算的**起点**（读最后 N 行要同时给 offset=-N 与 limit=N）；长行 column 从 1 到 1000000，到顶会明说读不到 |
| ListFiles | path、offset、limit | 分页列文件，默认 50 条；只要目录（给文件报错）；跳过隐藏、依赖、构建目录及符号链接；密钥文件按统一文案拒绝 |
| SearchFiles | query*、path、offset、limit | 有扫描预算的字面文本搜索；默认 30 条，路径/行号/预览 |
| Write | path*、content*、overwrite、append | content 每次最多 32000 **字符**（换行等转义后整个参数还须 ≤40000，否则先被输入上限拒绝），默认新建；显式覆盖/分块追加 |
| Edit | path*、old_text*、new_text*、expected_sha256 | 唯一精确匹配替换；expected_sha256 传了就必须是完整 64 位（传空串会报错，不再静默跳过校验）；不回显源码 |
| Shell | command*、working_directory、block_until_ms、timeout_ms | 本机命令执行；默认等待 30 秒（单次同步等待最多 60 秒），0 立即转后台；运行上限默认 10 分钟、硬上限 30 分钟；working_directory 相对路径按运行时根解析。子进程环境为白名单（PATH/HOME/locale 等），不继承 AGENT_*、OPENAI_*，密钥不会进命令输出 |
| AwaitShell | shell_id、block_until_ms、pattern、offset、stop | 增量读日志；pattern 为字面文本（只在最近 64KiB 输出里匹配），不是正则；offset 是输出**字符**游标；stop 杀进程组 |
| ReadToolOutput | output_id*、offset、limit、query | 持久原文分页/字面搜索；UTF-8 字节游标；只能读自己的日志。`limit` 两种模式都生效：读取=本页字节数（4–12000），搜索=最多几个命中（有效 1–30，缺省 30）；`query` 按 UTF-8 字节计、最多 1000 字节 |
| RecallMemory | query*、scope、limit、offset、full | 默认预览，full=true 返回最多 4 条完整原文，支持分页 |
| update_state | target*、action*；各目标附加参数 | 修改自己的记忆、资料、隐藏状态、头像、项目归属 |
| ListSections | offset、limit | 分页列分组名称（当前名称即 section_id），默认 20 条 |
| CreateAgent | name*、description、section_id | 创建持久同事；description 转为职责；每回合最多建 6 个；普通同事来信（inbox）无权调用 |
| UpdateAgent | agent_id*、name、description | 修改同事名字/职责；`agent_id` 可给 id 或**已存在的名字**（按 id 找不到再按名字）；两个字段都不给时不落盘（不会因空调用刷新 updatedAt、改动侧栏排序）；inbox 无权调用 |
| CreateChannel | name*、member_ids* | 建群，1–6 位有效同事；每回合最多建 1 个；inbox 无权调用 |
| UpdateChannel | channel_id*、add_member_ids、remove_member_ids | 增减群成员；调用者必须已在群中；不能删空；inbox 无权调用 |
| ManageRoomFlow | action*、room_id、flow_id、protocol、actors、reason | 受控群流程控制：start / pause / resume / cancel / status；仅流程协调者可控制已有流程 |
| SendToAgent | target_id*、message*、images、priority | 给同事或所在群传话；可按稳定 ID 或名字解析，优先用 ID |
| WebSearch | search_term* | 公网搜索，返回标题/URL/摘要；最多 5 条；正文用 WebFetch 抓；不是登录态服务查询 |
| WebFetch | url*、secretName、maxChars、offset | 公网文本分页，正文默认最多 12000 字符；逐跳检查及连接时 DNS 校验 |
| Task | description*、prompt*、subagent_type*、run_in_background | 只支持 executor；前台最多等 30 秒，之后后台；单次最长 10 分钟 |
| CheckSubagent | subagent_id、offset、limit | 只能看自己派出的工人；列表默认 20 条，保留完整 ID |
| MessageSubagent | subagent_id*、message* | 给工人排入纠偏消息；当前执行中的接收时机仍需核验 |
| StopSubagent | subagent_id* | 取消工人，使用其当前中止句柄 |
| TodoWrite | todos*、merge* | 按 agent 持久保存；重写至少 2 条，合并可 1 条，总量 ≤100 条 |

## 2. SendToUser 的四种输入

| type | 必要内容 | 路由与限制 |
| --- | --- | --- |
| text | content | 私聊写入同事对话线；群回合必须显式选择 to=room 公开发群或 to=dm 私发主人；群每回合上限 3 条 |
| attachment | url | 工作区内已有文件路径，可带 file://；复制到允许交付目录并写一条交付位置消息；群回合须用 to=dm |
| widget | widget.prompt、widget.options | 选项至少 2 个（2–6），每个含 label，可给 value；支持 helpText；multiSelect=true 当前报错；群回合须用 to=dm。**选项没有 style 字段**（曾声明未实现，已按 E5.8 移除） |
| secret-request | secret.name；可选 label/description | 弹遮罩输入，值进入 SecretStore，工具结果只返回密钥名字；群回合须用 to=dm |

`end_turn` 只对 `text` / `attachment` 生效（表示「这是最后一条，说完收尾」）。**提问类 `widget` / `secret-request` 会忽略它**：这两类的工具返回值就是用户的回答，agent-loop 一见收尾标记就返回、不再问模型，等于把刚拿到的回答丢掉（bug_zdrxbvtxbh4o）。

产品提示把 SendToUser 定义为私聊与群聊的统一出口。考虑到部分模型偶尔不会发起工具调用，私聊在“整轮完全没有调用 SendToUser”时会把最终正文作为兼容兜底；该正文不提前流式展示。一旦调用过出口，就不会再追加普通助手文本。群回合没有该兜底，只认工具写入的 posts。

群消息会作为内部经历进入成员的模型上下文，但不属于成员与主人的私聊时间线；私聊快照、实时事件和消息计数都会过滤这类经历。群回合省略 `to` 会被拒绝，避免本想私发主人却因默认值公开到群。

独立私聊回合默认不能 `to:"room"`。只有激活票据携带运行时签名的 `replyRoute`（受控流程签发的行动授权）时，才能把候选行动提交回原流程。提交走 `RoomFlowService.submitProposal`：校验授权、版本和协议后才公开；拒绝或过期版本不会先写群再回滚。工具成功返回“已向受控流程提交候选行动”，不表示行动已被接受为最终事实——接受由协议和流程服务决定。

可选参数 `delivery_refs` 最多 8 个已受理投递回执 id，供 `ReplyFinalizer` 核对“已发送”类陈述。没有对应回执时，不得把计划中的消息说成已经发出。

`end_turn=true` 会标记当前回合并让 AgentLoop 在该次出口完成后立即收尾，不再额外请求一次模型。widget 强校验 2–6 个选项及唯一 ID；multiSelect=true 会拒绝，allowCustom=false 当前不支持，会明确拒绝。

附件是文件交付能力，不等于图片上传、内联预览、消息附件寻址已经齐全。不得调用 attachment 传 https 地址后宣称远程图片已保存。

## 4. 协作与后台任务

SendToAgent 给同事写入收件箱和双向往来档案；给群写时间线、成员经历并逐个入队。两种发送都不等待模型执行，返回固定短句，回信属于之后的新回合。收件人不是发送者的子任务，停止发送者不会撤回消息或停止同事。priority 对同事表示队列优先，群忽略，不会打断正在进行的用户回合。受控流程中的正式交接不走普通 `SendToAgent`，由 `RoomFlowService` 签发授权后经收件箱唤醒；投递仍立即返回，但带 `flowId`/`grantId`/`replyRoute`。

### ManageRoomFlow

仅用于受控群流程，不生成聊天气泡。

| action | 必要参数 | 行为 |
| --- | --- | --- |
| start | room_id（群回合可省略，默认当前群）、actors（至少 1 个 `{kind,id}`） | 创建流程，房间进入 `managed`；默认协议 `sequential_turn`；调用者成为协调者，必须已是群成员；参与者可用 id 或名字 |
| pause | flow_id 或当前群活动流程 | 暂停、撤销全部活动授权 |
| resume | 同上 | 升版本、按协议 `next()` 签发新授权并唤醒下一行动者 |
| cancel | 同上 | 取消流程，房间回到 `open` |
| status | 同上 | 返回 id/status/phase/version/currentActors 的 JSON |

`pause` / `resume` / `cancel` / `status` 只有该流程的 `coordinatorId` 能调用。没有 `assign` / `commit` / `reject` 工具动作：确定性协议在候选行动提交时自动校验、归约和接棒。HTTP 控制入口 `POST /api/rooms/:id/flow/control` 供主人在 UI 上暂停/继续/取消，不经过该工具。

images 仅限 1:1，最多 4 张 HTTP(S) URL，每个地址最多 2048 字符、alt 最多 300 字符；不接受本地路径/base64，群图明确拒绝。图片贯通至视觉模型的 image_url 内容块，不将文字说明冒充图片；模型是否支持识图由供应商决定。同群内用 SendToUser 即时发言，不允许 SendToAgent 再次广播唤醒整组；私发和跨群保留传话深度。目标先按 id，再按名字回退；同名歧义列出可选 id，群名称候选仅限调用者所在群。

Task 工人没有用户完整对话上下文，prompt 要包含目标、背景、约束、交付标准。worker_id 与固定 agentId 不同。运行时注入 dataDir 时，worker/Todo 身份与状态持久化；重启不自动重放可能含副作用的旧工作。Task 的 resume、file_attachments、videoReview/watchVideo/computerUse 未在当前 schema 实现。

纠偏在工人当前一段工作结束后消费，最多积压 8 条/32000 字符；已结束的可再次发消息续跑。工人不能再次 Task、创建同事/群或 SendToAgent；停止/超时会取消模型和登记的 Shell。工人每次具体操作进入 ToolInvocation 账本。轮数/工具配额耗尽为 incomplete，异常为 failed，超时为 timed_out，重启中断为 interrupted；不再统称 done。done 仅表示工人已答复，不代表独立验收通过。

## 执行结果、日志与任务恢复

工具执行器使用结构化 `ToolResult`，保留文本 `execute` 兼容接口。消息仍保留原来的 result/ok，新增可选 outcome 元数据。原文以 `Error:` 开头不会被判失败；自定义工具应抛异常或返回 `toolError(code, message)`。

Shell 原文自动保存；其他工具结果超过可见额度时也落盘。默认单日志 32MiB、总正文 256MiB、最多 1000 条，关闭日志保留 7 天（触发读写或重启时清理；配额不足可提前清理旧关闭日志）。活跃日志不清理；无法继续保存时显式标记 storageTruncated，不宣称原文完整。ReadToolOutput 默认读 8000、最多 12000 字节；搜索每次扫描最多 256KiB、`limit` 决定本次返回几个命中（有效 1–30，缺省 30）。AwaitShell 保留旧字符游标，不能与 ReadToolOutput 的字节游标混用。

每次运行保存独立任务快照，记录原目标、已读/已改文件、待办、近期执行证据、未决工具调用和阶段交接；已停止快照全局最多保留 500 个，完整历史另存。刚停止的任务可在私聊明确说“继续”，或通过发送接口的 resumeTaskId 精确选择；普通新任务不自动关联。GET /api/agents/:id/tasks 返回分页摘要，GET /api/agents/:id/tasks/:taskId 返回完整快照。恢复只带回证据，不自动重放工具或回滚文件；仍须核对实际产物。轮数/工具总配额用尽不会自动续跑。

续跑触发：私聊发送“继续”“继续上个任务”“继续刚才的任务”“接着做”或“恢复上个任务”，只关联当前私聊最近一次未完成/失败/中断/取消的任务；工人停止后用 MessageSubagent 续跑。快照上限：最近 24 条工具证据、读/改文件各 60 个、待办 100 条，恢复简报最多 24000 字符；快照作为历史数据注入，不提升为 system 指令，也不覆盖最新用户要求。

## 5. 文件、网络与数据边界

- Read 使用本机文件路径，不限制在项目根；仅文本。大于 256KiB 也能分段读，扫描量最多 32MiB；每行最多返回 2000 字符，可按 column 续读。
- **密钥文件默认拒绝**（OPT-07）：数据目录下的 `secrets.json`、`model-config.json`、`room-flows/secret.key`，以及项目根的 `.env`、`.env.*`（`.env.example` 放行），Read / Write / Edit / SearchFiles / ListFiles 一律拒绝或跳过；判定按真实路径（realpath），文件本身或数据目录是符号链接也挡得住。Shell 在启动进程前做保守的字面检查，命令里出现这些路径即拒绝。拒绝信息统一说明「需要密钥请让用户在界面的密钥框里提供，并用 secretName 引用」。这是默认拒绝，不是沙箱：命令里用变量、命令替换或编码后拼出来的路径挡不住（完整沙箱不在本任务范围）。名单实现在 `src/tools/sensitive-paths.ts`。
- Shell 在本机运行，工作目录需有效；它不是云电脑。执行器需负责进程生命周期、超时、输出截断和取消，恢复时未知动作必须核对。
- SendToUser 附件允许工作区文件或已经处于交付目录中的文件；校验 realpath，最多 50MiB，重名不覆盖。目录白名单由 AGENT_DELIVER_DIRS 配置。该约束不等同于整个 Shell/Read 都有同样边界。
- WebFetch 的内网与协议检查在 web.ts；失败应区分网络、超时、格式和访问边界，不伪造已读页面。
- 共用用户笔记不是其他同事私聊的读取入口；项目笔记只能在当前可见项目范围内使用。
- SecretStore 不把值放进普通工具结果和消息。后续设置/连接器统一引用密钥名称，敏感值不复制到工作摘要。

插件安装和外部发送遵循用户明确授权与产品交互要求；不能把宿主工具中的规则或账号状态当成 AgentBot 已具备的能力。连接器自有工具由插件注入，避免在 Runtime 写死服务商。

云电脑、注册机器和跨机器复制不在范围。CloudAgent/request_scm_connect 等云端仓库代理属于待定扩展，不能为了补平台数字而实现。当前不以“凑齐 46 个工具”为验收标准，以用户流程和工具真实行为一致为准。

## 7. 维护规则

新增或修改工具时同步源码 schema、执行校验、工具参考及对应行为测试。若工具只是包装一个服务，测试重点是参数转换、权限和失败返回；实际生命周期在服务集成测试覆盖。

未来从同一工具注册表生成列表和参数骨架，人工只维护限制与产品语义。工具名称兼容性单独迁移，代码模块重命名不随意改变模型可调用名称。
