# 工具边界审计与限额

更新：2026-09-27（写代码能力：上下文默认 1M 且超长自动收缩、渐进压缩、每轮额度可配、搜索/编辑增强）。本次覆盖当前完整装配的 25 个工具（原 24 个 + ManageRoomFlow）。限额由 `src/tools/limits.ts` 与各工具的 schema/服务共同执行，不只是提示词约定。未登记在 `TOOL_LIMITS` 的工具使用回退上限 16000/8000。未新增 token 用量、费用或缓存命中率统计。

## 全链路保护

- 每轮工具调用次数、成功工具正文总量及调用参数总量都有上限：库默认 128 次、各 256000 字符（`src/tools/limits.ts`，直接调用 AgentLoop/单测用）；服务端按 `AGENT_MAX_TOOL_CALLS` / `AGENT_MAX_TOOL_CHARS` 注入，默认 256 次、各 1000000 字符，工人同一口径。单批最多 8 个。输出预算不足以容纳下一个工具的上限时，先拒绝该调用，避免完成副作用后丢失回执。同参数失败 3 次后不再执行。
- 轮数库默认 32、服务端默认 64（`AGENT_MAX_ITERATIONS`，8–400）；剩余 8 轮、16 次工具调用或输入/输出额度低于 64000 字符时，在当次请求末尾提醒优先修改、验证与交付，不反复写入历史。硬配额拒绝后不再空转；同批剩余调用仅补未执行回执。
- 达到轮次/工具总配额后，额外最多一次无工具的阶段交接请求（30 秒截止，正文最多 4000 字符），没有新增修改权限。空/截断/夹带工具/失败/超时的总结改用最近 6 条有界执行记录兜底；取消或抢占不交付迟到总结。轮数为 `max_iterations`，工具总配额为 `tool_limit`，任务均为 incomplete，不冒充完整验收或自动续跑，已执行副作用不会回滚。
- 每一次模型请求前，按消息、工具定义及序列化包装重新估算上下文。每个回合的上下文预算默认 1M（`AGENT_MAX_CONTEXT_TOKENS` 可改，不低于 16000）。模型实际窗口更小时会报超长：运行时从报错里读出它的上限（读不出就逐步砍 40%），按新预算压缩后重试，最多两次；学到的上限按模型记住，之后的回合直接按它组装，换模型配置后清空重新探测。模型设置页不再填上下文窗口。预算中预留 8192 输出和 15% 估算余量。估算不等于精确 tokenizer；超长识别只认 400/413/422 或流内报错，429 限流等不会被当成窗口太小（`src/llm/context-overflow.ts`）。
- 超预算时从最早的组开始压缩工具大正文（保留 1000 tokens）和历史长参数，压到可用预算的 90% 即停；同一回合内沿用已压缩的边界，前缀不每轮变动，最近读到的原文保持完整。全部压过仍放不下才成组移出较早调用/结果；不修改磁盘历史。固定系统规则和当前用户任务保留，连固定内容都超限时明确失败。
- 不完整的历史工具调用不会以缺少结果的非法形态提交；`finish_reason=length` 的当前批次不执行，最多纠正 2 次。流式 EOF 缺少结束原因、非法 JSON、正文 >64000 字符或总流 >2MiB 均明确失败；非流式响应 ≤512KiB。
- 摘要水位只推进到实际完整送给压缩器的消息批次；相同时间戳一起处理。单个历史批次 >48000 字符时不伪造已覆盖，原文保留。
- 抢占/取消后不再启动下一项工具；迟到结果可以回填执行账本，但不能写入旧聊天回合。
- 固定规则与动态记忆分为独立消息；工具定义按名称排序，尽量稳定请求前缀。缓存命中仍取决于具体服务商/模型，未增加供应商专有开关或命中统计。

## 已修复的非数量问题

- Read 的大文件拒绝发生在 offset/limit 之前；现改为有扫描预算的流式读取。
- Read 分页改按实际行号、正文、换行与截断标记计量，取消每行虚扣 80 字符；正文和总输出上限不变。截图对应的原始 1053 行 HTML 只读验证由 12 页降为 6 页，不再因保守预扣消耗大量执行轮次。
- 写网页不得不用长 Shell，且 Shell 将整段命令再回传；新增 Write/Edit，Shell 只回命令摘要和增量日志。
- 工具数组 schema 写成 properties 或 string；已改成 items 并逐项校验，工作台仍兼容合法 JSON 数组字符串。
- Task 的 maxWorkers 参数未传到管理器；现已接线，工人不能递归派工，父级取消会传播。
- 项目记忆归属静默回退；现缺归属/无权限会失败。RecallMemory 补上字面命中回退，避免长记录因相关度门槛而查不到。
- 附件来源与 Shell 工作目录不一致；已在交付白名单中的文件可原地交付，工作区产物复制时不覆盖同名用户文件，路径使用 realpath 校验。
- WebFetch 自动重定向绕过初始检查；现逐跳校验、跨源移除 Authorization，实际连接时校验 DNS 解析地址。拒绝压缩响应（要求 identity），避免未受控解压。
- AwaitShell 文案称 RE2，实际执行 JS RegExp；改为明确的字面量匹配，消除用户正则回溯风险。
- 密钥文件原先没有任何读取边界（OPT-07）：数据目录的 `secrets.json`/`model-config.json`/`room-flows/secret.key` 与项目根 `.env`/`.env.*` 现在被 Read/Write/Edit 拒绝、被 ListFiles/SearchFiles 跳过，Shell 在执行进程前按字面检查拒绝；判定用 realpath，文件软链与数据目录自身是软链都挡得住（`src/tools/sensitive-paths.ts`，回归 `test/sensitive-paths.test.ts`）。这是默认拒绝，不是沙箱：命令里用变量/命令替换/编码拼出来的路径仍可能绕过。
- SearchFiles 只扫排序后的前 100 个文件，offset 翻的是命中数，扫描预算又每次从头计，第 100 个之后的文件永远搜不到（本仓库 `src` 下搜 `class ToolRegistry` 返回「没有命中」）：现单次按 64MiB/15 秒预算搜完整个范围，先整文件粗筛再逐行定位；只有命中太多才给 next_offset，预算用完会指出从哪个文件起没搜，不再给原地打转的翻页提示。目录扫描只对可能同名的文件做密钥 realpath 核对，上限放宽到 20000 条目录项。
- Edit 没命中与命中多处共用一句报错，CRLF 文件里按 Read 输出（已去 \r）写的多行 old_text 永远匹配不上：现区分两种情况并给出行号；没命中时识别 Read 行号前缀、只差空白/缩进（附原文）、首行对得上后面不对三种情形；CRLF 文件自动按 CRLF 匹配与写回；成功后回显改动处附近几行。
- Shell 子进程白名单缺代理（`HTTP(S)_PROXY`/`ALL_PROXY`/`NO_PROXY`）、`SSH_AUTH_SOCK` 与各语言工具链/镜像变量，需要代理或 SSH 的 npm/pip/git 在智能体里失败：现按名单放行，`AGENT_*`、`OPENAI_*` 与其他变量仍不继承。
- DeepSeek V4 起自家模型默认开思考，界面关掉思考时请求里什么都不发，开关不生效：现对 DeepSeek 官方接口上的 `deepseek-*` 模型显式发 `thinking.type=disabled`，其他供应商不变。流式解析在思维链与正文同一分片到达时会丢正文，已修复。
- ManageRoomFlow 既没登记限额（走 16000/8000 回退），也没登记恢复分类（按未知工具 manual），schema 还绕过了 `defineTool` 的统一边界（OPT-08）：现登记 8000/4000、显式归入 manual 集合、改走 `defineTool` 让字符串/数组上限与 `additionalProperties:false` 生效；新增 `test/tool-registration.test.ts` 遍历运行时工具面，任何未登记限额或未登记恢复分类的工具都会让测试失败。

## 验证与剩余边界

测试：`test/tool-limits.test.ts`、`test/context-limits.test.ts`、`test/agent-loop-limits.test.ts`、`test/provider-stream.test.ts`、`test/context-window-budget.test.ts`、`test/context-progressive-compaction.test.ts`、`test/context-overflow.test.ts`、`test/file-tools-coding.test.ts`、`test/worker-coding.test.ts`，同时回归已有工具、群投递、停止、抢占、持久化测试。模型请求均用本地假服务/假 Provider；没有用真实付费 API 验证缓存命中。第 32 轮刚完成 Edit 的复现场景验证后续只交接、不再执行工具；提示词调整不保证模型一定选择最优编辑路径。

这些是资源边界，不是操作系统沙箱。Read/Write/Edit/Shell 仍能按产品设计访问本机路径；执行不可信命令仍需独立权限/沙箱。文件原子提交有工具内锁和改动核验，但不保证抵御恶意外外进程在检查与提交之间抢写。Shell 的进程组取消按 POSIX 实现，Windows 仍仅能保证终止直接子进程。搜索超过扫描预算会明确提示缩小路径，不承诺对超大仓库一次搜全；长行超过预览范围时需 Read 按列核对。

Shell 与工人派生的子进程不继承后端进程环境：`src/tools/services/child-environment.ts` 用白名单只放行 PATH/HOME/locale/终端/node 工具链，以及代理、SSH agent、各语言工具链位置与镜像源等开发必需变量，`AGENT_*`、`OPENAI_*` 一律不给——模型密钥（`AGENT_API_KEY`）因此不会进入工具输出、模型上下文或落盘日志。这是密钥边界，不是命令权限边界：智能体仍可执行它有权限执行的本机命令。
