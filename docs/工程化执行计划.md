# AgentBot 整体工程化与后续执行计划

更新：2026-09-12。本文是项目唯一的后续执行清单。架构规则见[架构设计](./架构设计.md)，当前启动方式见[使用与开发说明](./README.md)，已实现工具见[工具参考](./工具参考.md)。

## 1. 目标、范围与执行方式

产品目标：agent 是长期合作的固定同事，持续积累自己的经历，能接住消息、记录承诺、跟进多件工作。用户始终找同一个同事聊天，不需要按工作新建会话。

工程目标：职责明确、改动范围可控、数据可恢复、接口有契约、构建可复现、出现问题能追溯。继续使用 TypeScript、Node、React 和 Electron，以本地单用户、单后端进程为第一阶段部署形态。

本轮只完成文档收敛、旧图文清理和基线核对。下面的代码拆分、存储迁移、产品功能均为待执行，不能因为写了方案就标成完成。

执行规则：按阶段依赖推进，每个条目以独立、可验证的小改动交付；先保持行为的拆分，再改业务语义；每完成一项更新本表及验证记录。遇到阻塞记录具体原因和可继续的条目，不重新复制一份计划。

### 3.3 目标源码结构（分阶段建立）

```text
src/
  app/                  装配根、配置、生命周期；唯一负责 new 各服务的地方
  server/               HTTP 入口、routes、输入校验、presenters、SSE、静态托管
  agent/                固定身份、组装、AgentLoop
  conversation/         收信、消息归属、同事经历
  runtime/              调度、执行、停止、收件箱消费、恢复
  work/                 工作、步骤、等待、委派
  room/                 成员、点名、发言规则、扇出
  context/              上下文选择、预算、渲染
  memory/               分层、检索、去重、压缩、抽取
  tools/
    builtin/            工具定义及参数转换
    services/           shell、工人、附件等实际执行能力
  storage/              Repository、JSON 适配、SQLite、迁移
  llm/                  Provider 协议与实现
  interaction/          用户提问/回答
  secret/               密钥存储
  workbench/            工作台操作服务
  cli/                  命令行入口
  index.ts              公共导出；import 不启动 CLI
shared/
  contracts/            HTTP/SSE DTO，纯类型和纯校验，不引用 Node 或 React
web/src/
  app/                  页面外壳、应用初始化
  features/
    chat/               消息 reducer、发送、流订阅、滚动、聊天视图
    workspace/          侧边栏、同事/群管理
    work/               手头工作与等待面板
    memory/             记忆面板
    settings/           设置
    interactions/       问答卡
  shared/               通用 UI、API transport、格式化函数
  styles/               tokens、base、layout；组件样式靠近组件
desktop/                启动、窗口、后端生命周期、打包
test/                   unit、integration、fixtures；web 交互测试逐步就近放置
scripts/                可重复执行的检查、迁移校验、打包辅助
docs/                   上述四份文档
```

初期保留根/web/desktop 三个 npm 包和当前锁文件，不同时更换包管理器。共享 contracts 建立时明确 TypeScript rootDir/outDir、前端 bundler 和测试路径，禁止直接让 web 引入后端运行模块。需要独立包时再配置 npm workspace 和包导出，一次迁移完成依赖与锁文件，不能留下两套互相覆盖的安装方法。

依赖规则：HTTP 与工具调用应用服务；应用服务组合领域及 Repository；存储和 Provider 实现接口。领域不引用 HTTP/React；工具不获取整个 Runtime；前端不自行重写服务端 DTO；跨模块不读取别人的内部 Map。新增公共工具函数需有明确归属，避免 `utils.ts` 再长成总文件。

- [ ] **E4.5 executor 收尾**：改造已有 Task 工人，持久状态、完成投递、纠偏信息和取消关系；限制递归派工及累计并发；恢复不依赖内存 Map。
- [ ] **E4.6 上下文与记忆修复**：保留发送者、频道、工作；工作状态不由旧记忆覆盖；压缩只推进实际覆盖的消息序号；输入、工具 schema、输出预留统一预算。
- [ ] **E4.7 手头工作界面**：侧边栏仍以同事/群为主；右侧展示目标、进展、等待对象、下一步、交付物；步骤和日志按需展开。

验收：隔日继续同一工作；修订只测登录后不再跑旧全量目标；闲聊不丢旧任务；重启后等同事回复仍能接上；停 A 的委派不影响 B 的独立工作；工具完成不自动等于业务验收完成。

用户亲自发给同事的停止建议立即阻止新动作，并中止目标执行；这不同于当前“用户回合结束后才处理停止”的规则。该行为调整须独立提交、更新架构当前状态与回归用例，不能藏进 E2 的结构重构。

## 6. 通用验收与数据迁移

代码改动至少通过与改动相关的类型检查、行为测试和构建；样式迁移补视觉检查。优先覆盖跨模块真实问题，不为简单搬文件增加复述实现的测试。

关键验收集合：身份不随会话变化；群成员独立决策；普通插话不丢旧工作；停止可关联；消息去重；工具参数拒绝无效值；未知副作用恢复；等待跨重启；迁移失败保留原数据；不同同事的私有记忆不串用。

存储迁移流程：停旧写入 → 完整备份 → 导入并保留 ID → 核对数量/引用/顺序/待投递项 → 切换版本标记 → 新链路单写。旧群副本无法精确匹配时标 legacy，禁止按文本相似猜合并。不能从所有历史聊天猜哪些旧工作还没完成。

切换前可回滚到旧存储；切换后先导出新增数据并执行可核验回迁，不能直接覆盖。旧密钥和产物不进入测试夹具或文档截图。所有迁移与 clean 命令提供明确目标路径、预览和限定范围。
