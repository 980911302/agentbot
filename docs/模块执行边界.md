# 模块执行边界与故障恢复

这批调整补齐工具工人、日志存储、任务续跑、记忆后处理和收件箱的跨模块约束。
聊天命令、事件水位和快照协议仍以《聊天运行与恢复协议》为准。本项目仍是本机单实例模块化应用，不引入消息中间件或微服务。

## 边界与事实源

| 边界 | 持久事实 | 运行时职责 |
| --- | --- | --- |
| 工具授权 | Worker 的 ExecutionAuthority、Run 的 RunContinuation | 当前注册表授权与原授权取交集，不因派工/自动续跑扩大能力 |
| 消息日志 | 私聊及群的 JSONL 文件 | JsonlLog 统一加载、尾部隔离、修复、追加与清空；每条对话串行。读侧分档（OPT-02）：`view` 只读不拷贝、`tail` 只复制尾部、`filter` 按谓词（MessageStore 的 `byRun`/`latestUser`/`recent` 走这些路径）；缓存按最近使用淘汰（`cacheMaxKeys`，默认 64 个 key） |
| 任务恢复 | RunLedger.continuation | 还原来源、模型、群目标、简报、协作深度、交付方式与授权上限 |
| 记忆后处理 | 提交成功的记忆条目 | MemoryMaintenance 不占聊天执行位；新回合、停止及关闭取消旧工作 |
| 来信投递 | AgentInbox 的 pending/claimed/failed、availableAt、owner/epoch | DeliverySession 持有并续租；InboxScheduler 到期唤醒，定时器可重建 |
| 受控群流程 | RoomFlowStore 的 flow/state/grants/events/outbox | RoomFlowService 唯一状态转换入口；RoomFlowScheduler 只消费已持久化的 grant_ready；迟到提案按版本/授权拒绝 |

## 1. 授权继承

- AgentLoop 从实际 ToolRegistry 装配授权，不接受模型参数伪造工具名单。
- Task 将授权快照复制给工人，同时保留本轮模型和项目范围。
- 工人每段执行重新读取父智能体的当前权限，和原快照取交集；项目权限同样取交集。
- 自动续跑使用当前注册表与原任务授权的交集，不能因为系统新增工具而扩大原任务能力。
- 旧工人没有授权快照时默认无工具；应由父智能体重新派发有明确授权的新任务。
- 这是应用层工具与记忆作用域约束，不是操作系统沙箱。已授予的 Shell/Read 本身仍有本机访问能力。

## 2. JSONL 日志恢复

- 只有最后一条非空记录损坏才允许修复；中间损坏报错并拒绝追加。
- 修复前把损坏的原始字节写入同目录 `.jsonl.corrupt-<uuid>` 文件，再截断到最后一个完整行边界。备份失败时不截断。
- 完整 JSON 末行缺少换行符时先补分隔符，避免新消息粘连。
- 读取、首次修复、追加和清空共用同一日志锁；追加失败后丢弃缓存，下一次重新核对文件。
- 备份不自动清理。这里不声称跨文件事务、断电级 fsync 保证或多实例安全；服务仍需使用现有单实例锁。

## 3. 自动续跑不是重新造一条私聊

- RunContinuation 只保存可序列化语义，不保存工具函数、AbortController、Promise 或旧发言缓冲。
- 群任务恢复后创建新的空发言缓冲，仍用 SendToUser 群出口，经 RoomDispatcher 交付到原群并广播给成员。
- 群已解散/智能体离群时撤销旧任务，不降级为私聊。
- 旧的非私聊任务记录若缺少完整续跑描述，不猜测来源，不自动执行；需要重新派发。
- 模型前压缩、模型调用、模型后交付都遵守取消规则；不是只有 AgentLoop 内才识别抢占。

## 4. 记忆与压缩的提交边界

- 记忆抽取是独立的最佳努力后处理，最多运行 30 秒，不阻塞聊天完成和下一轮输入。
- 抽取仅使用当前任务及当前 run 的消息，避免把其他回合混进一次抽取。
- 新回合/停止/关闭取消旧后处理，模型请求带取消信号；即使供应方忽略取消，迟到结果仍被拒绝。
- MemoryStore 在异步加载后、修改内存条目之前重新核对提交条件。
- 上下文压缩仍在模型前执行，但现在可取消，摘要提交前也核对执行权。
- 后处理队列不持久化：进程中断可能少抽取一轮记忆，原始消息仍保留。不承诺重启自动补抽取。

## 5. 租约和调度

- ack/nack/release/checkpoint/renew 必须携带领取时的 owner 和 epoch，同时要求租约未到期。
- 领取和查看返回快照，后续换手不会悄悄修改旧调用方持有的租约。
- 一个 DeliverySession 管一个领取批次；续租与确认串行。续租失效即取消该批执行。
- InboxProcessor 对每个智能体只保留一个在途消费 Promise，避免递归或并发 drain 重复领取。
- InboxScheduler 读取持久的到期时间安排唤醒；启动时包含尚未到期的退避任务，不依赖下一条用户消息。
- 正常关服停止调度和后台记忆，并取消执行中的模型请求；不把定时器遗留到下一个服务实例。

## 6. 重试与副作用

- 普通来信和排队群任务都在模型执行前记录投递检查点。
- TaskProgress 在可能有副作用的工具执行前记录 mayHaveSideEffects，不能仅凭会被裁剪的最近工具列表判断。
- 确认尚无副作用的失败执行按现有上限退避重试；可能已有副作用或缺少安全依据的旧记录进入 failed，提示核对产物后重新派发。
- “收到并确认一封信”和“业务任务最终验收通过”仍不是同一概念；不承诺任意 Shell/外发 exactly-once。
