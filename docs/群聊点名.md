# 群聊点名

整理日期：2026-09-15

本文只描述房间模式 `open`（普通群聊）。房间进入 `managed` 后，公开消息仍大家可见，但**不会**按点名扇出全员；谁能行动由流程授权决定，见 `docs/群流程与行动权.md`。

`@` 决定的是**谁必须开口**，不是谁能看见、也不是谁有回合。

在场的人这一轮都会被叫醒。没被点名也可以说话，但默认该沉默。被点名的必须回。消息意图是面向全群的社交交流时，每位在场成员各回应一次，然后结束。

投递、入队见 `协作投递.md`。本文只写点名与开口。

---

## 1. 三条分开

| | 看见这条群消息 | 有一个群回合 | 必须 `SendToUser` |
| --- | --- | --- | --- |
| 在场、没被点名 | 是 | 是 | 否。没有新内容就不出口 |
| 面向全群的社交交流 | 是 | 是 | 是，每人一条后结束 |
| `@名字` 点到的人 | 是 | 是 | **是** |
| `@everyone` | 是 | 是 | **全员是** |
| 不在群里的人 | 否 | 否 | — |
| 发送方自己（主人或正在说的同事） | 是 | 本轮已经在说话，不再给自己扇一回合 | — |

「叫醒」= 收件箱入队、稍后跑模型。
「开口」= 这一轮至少一次 `SendToUser`（进当前群）。
整轮零次出口 = 沉默，合法，不是失败。

不要做成「只有被 @ 的人才跑模型」。也不要做成「在场的人都必须回一句」。

---

## 2. 平台实际怎么判

主人或同事在群里发一条。运行时：

1. 按**发送时的完整成员快照**解析 `@`（忙不忙不影响谁被点到）。
2. 群时间线落一条。
3. 每个**其他**成员入队，带上本轮上下文：
   - `summoned`：被 `@名字` 或 `@everyone` 点到
   - `everyone`：这条是不是 `@everyone`
   - `speaker`：谁触发的
   - `roundId`：这一条公开消息的 id
4. 调度器空闲就跑。忙的人信留着，空下来再跑，不丢。

每个成员的群简报只写自己的点名状态：

- 被点名：`**有人点名了你，你必须开口。**`
- `@everyone`：`**有人 @everyone，你被点名了，必须开口。**`
- 没被点名：`没有人点名你。`

模型用 `SendToUser` 开口。没被点名且没什么可补的：不调出口，直接结束。

---

## 3. `@` 怎么认

正文里的 `@名字`，按成员**当前名字**匹配，长名优先，避免 `@测试` 误打到「测试运维」。

```
@测试运维 159 今晚能发吗
@everyone 各自报一下分支
@测试运维 @知识库服务 你们对一下库
```

规则：

- `@名字` 只点这个人。其他人仍有回合，不强制开口。
- 一条里可以点多人，被点到的都是 `summoned`。
- `@everyone` 全员 `summoned`（发送方自己除外）。
- 同时写了 `@everyone` 和 `@某人`：按全员点名即可，不必再记一份名单。
- `@` 对不上任何成员：当普通字，谁都不算被点名。
- 新成员看不到入群前的时间线，也不会被旧回合补点。

解析用发送那一刻的成员表。有人中途离群：已入队的信在领取时发现人不在了，撤销，不跑模型。

---

## 4. 没被点名的人什么时候开口

先处理一个社交例外：消息意图是面向全群的社交交流时，每位在场成员都应各回复一条短消息，然后结束。回应不得提出方案、分派工作、点名同事、汇报旧进展或发起后续议程。这不改变 `@` 的强制点名语义。

除全群社交回应外，其他未被点名者只有同时满足才该 `SendToUser`：

1. 内容实质，不是「同意 / 收到 / 好的」；
2. 别人（含已被点名的人）还没说过；
3. 归自己管。

否则沉默。

反例（不该开口）：

- 被点的是测试运维，知识库服务只想附和「对」
- 把整楼再总结一遍
- 重复点名人已经在说的结论

正例（可以开口）：

- 主人 `@测试运维` 问 159，知识库服务发现这次发版会动**它**那份库，而测试运维还没提——补一句风险，并 `@测试运维` 让他接着说

没被点名却开了口，不算违规；乱开口才是产品问题。简报要把「可以沉默」写死，运行时不要因为没出口就重试、报错、补一句「在」。

---

## 5. 被点名的人必须回

被 `@` / `@everyone`：

- 必须至少一条进群的 `SendToUser`
- 可以很短：「159 今晚可以发，我来推。」
- 可以是「我这边没有。」「不是我的范围，应该问 @知识库服务。」
- 不能不出口。运行时不要因此自动代回；那是模型的回合，它该自己说

被点名后去干活（查环境、读文件）再开口：先干再 `SendToUser`，和群回合「先干活再说话」一致。

群里的停止令：不能紧急打断别人。被点名的人简报里看到停止，回一句确认停了即可，不要继续旧活。没被点名的人看见停止令：不强制开口。

---

## 6. 同事发言里再 `@`

成员开口后，运行时再解析他正文里的 `@`。

- 点到一个**这一轮还没被点过、或需要再回应**的人：再入队一封 `kind=room`，`summoned=true`，`recallCount` +1
- 简报改成：`**有同事在发言里点名了你，你必须开口回应。**`
- 每人每个 `roundId` 有次数上限（AgentBot 用 `ROOM_MAX_RUNS_PER_MEMBER`），防止互相 @ 打转
- 这是入队，不是发送方同步把他们跑完

```
主人：@测试运维 159 能发吗
测试运维：可以，但库要 @知识库服务 先确认迁移
知识库服务：（第二趟被叫醒，必须回）迁移已在 team-edition，可以跟。
```

旁观的人第一趟可以沉默；被同事点到之后第二趟变成必须开口。

---

## 7. 调度（可留，但别堵出口）

AgentBot 现在的三波可以留，当作**队列消费者**的策略，不要套进 `SendToAgent` 的返回值：

1. **被点名的**，串行。后者能看见前者已经公开的话，少重复。
2. **在场未点名的**，并行。同波次互相看不见，但看得见第 1 波。
3. **同事发言引发的新 `@`**，串行，直到队列空或达到每轮上限。

主人或 `SendToAgent` 往群里贴一条：时间线 + 入队 + 立刻返回。三波在调度器里跑。

当前群回合里有人 `SendToUser`：只追加时间线、解析 `@`、入队被点到的人。不要对全体再扇一轮。

---

## 8. 简报怎么写（成员各看各的）

同一轮、同一条主人的话，三个成员三份简报：

```
房间：白泽联调
在场同事：测试运维、知识库服务、AI服务
这一轮由「主人」触发。
```

然后只多一句：

- 测试运维（被点名）：`**有人点名了你，必须开口。**`
- 知识库服务（没点名）：`没有人点名你。`
- 全员 `@everyone`：每人一句 `**有人 @everyone，你被点名了，必须开口。**`
- 面向全群的社交交流：每位成员各回复一条短消息并结束，不点名、不引出工作

「这一轮已经有人说过」只列**已经公开**的 `SendToUser` 正文，给后开口的人接话用。同波并行的旁观者看不到彼此未公开的草稿。

不要把群纪律写进每个人的 `instructions`。进群再注入，见 `提示词.md`。

---

## 9. 和私发的区别

| | 群里 `@测试运维` | `SendToAgent` 给测试运维 |
| --- | --- | --- |
| 谁看得见 | 全群 | 双方 + 主人在传话里能看见 |
| 其他人有没有回合 | 有，默认沉默 | 没有 |
| 测试运维必须开口吗 | 必须进群回 | 有实质才回同事；纯收到不回 |
| 当前群能这么喊吗 | 正文写 `@名字` 即可 | 禁止再 `SendToAgent` 当前群 |

要把一个人从旁观拉进必须开口：在群正文写 `@他`。不要为了点名去私发再让他回群。

---

## 10. 完成标准

1. 主人 `@A`：A、B 都入队；A 的简报 `summoned=true`，B 为 false。
2. A 至少一条群内 `SendToUser` 才算本轮成功开口；B 零次出口算沉默，不重试、不报错。
3. `@everyone`：除发送方外全员 `summoned=true`。
4. A 的发言里 `@B`：B 再入队且必须开口；每人每 `roundId` 不超过上限。
5. `@` 对不上任何人：全员 `summoned=false`。
6. 解析按发送时成员快照；离群后领取到的信撤销。
7. 工具返回 / HTTP 不包含「谁开口、谁沉默」；那是事件，给界面用。
8. 面向全群的社交交流：所有成员的简报都要求各回复一条短消息并结束，且不得形成新的点名或任务链。

单测断言入队标记和是否要求开口，不要等模型把整组说完。
