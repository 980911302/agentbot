# 链路文档

> 本文逐步说明每条链路「一次请求从进入到落地，中间到底发生了什么」。
> 用于排查问题、理解行为、评估改动影响。

整理日期：2026-09-11

## 0. 链路总览

```
                      ┌──────────────────┐
   用户输入 ──────────→│  前端 App.tsx     │
                      └────────┬─────────┘
                               │ 按频道类型分叉
              ┌────────────────┼────────────────┐
              ▼                                 ▼
     kind === 'agent'                   kind === 'room'
     POST /api/chat                     POST /api/rooms/:id/messages
     ─ 单智能体回合 ─                    ─ 扇出给全体成员 ─
              │                                 │
              ▼                                 ▼
     AgentRuntime.send()               AgentRuntime.postToRoom()
              │                                 │
              └────────────┬────────────────────┘
                           ▼
                  AgentRuntime.runTurn()   ← 核心回合
                           │
        ┌──────────────────┼──────────────────┐
        ▼                  ▼                  ▼
   压缩（可选）      组装上下文          模型-工具循环
   Compactor        ContextBuilder      AgentLoop
        │                  │                  │
        └──────────────────┴──────────────────┘
                           ▼
                    记忆抽取（回合后）
```

三条主链路：

| 链路 | 入口 | 扇出 | 详见 |
| --- | --- | --- | --- |
| **私聊** | `POST /api/chat` | 无 | §1 |
| **群聊** | `POST /api/rooms/:id/messages` | 全体成员 | §2 |
| **智能体 1:1** | 工具 `send_to_agent` | 单个同事 | §3 |

## 1. 私聊链路（单智能体回合）

### 1.1 时序

```
前端                     HTTP                AgentRuntime              LLM
 │                        │                       │                    │
 ├─ POST /api/chat ──────→│                       │                    │
 │                        ├─ 校验 text/botId      │                    │
 │                        ├─ isBusy? → 409        │                    │
 │                        ├─ writeHead(SSE)       │                    │
 │                        ├─ send(botId, text) ──→│                    │
 │                        │                       ├─ 加锁               │
 │                        │                       ├─ get(agentId)      │
 │                        │                       ├─ append(user msg)  │
 │ ← event: message ──────┼───────────────────────┤ emit               │
 │                        │                       │                    │
 │                        │                       ├─ buildAgent()      │
 │                        │                       │  └ 读 memory refs  │
 │                        │                       │  └ 读 compaction   │
 │                        │                       │                    │
 │                        │                       ├─ maybeCompact() ──→│ (仅在超阈值时)
 │ ← event: compacted ────┼───────────────────────┤ emit               │
 │                        │                       │                    │
 │                        │                       ├─ builder.build()   │
 │                        │                       │  └ 七段组装         │
 │ ← event: context ──────┼───────────────────────┤ emit(含分层用量)     │
 │                        │                       ├─ touchSurfaced()   │
 │                        │                       │  └ 回写 lastSurfaced│
 │                        │                       │                    │
 │                        │                       ├─ AgentLoop.run() ─→│
 │ ← event: iteration ────┼───────────────────────┤                    │
 │ ← event: message ──────┼───────────────────────┤ ← 文本/工具调用      │
 │                        │                       │  └ 执行工具         │
 │ ← event: message ──────┼───────────────────────┤  └ 工具结果落库      │
 │                        │                       │  （循环直到无工具调用）│
 │ ← event: final ────────┼───────────────────────┤                    │
 │                        │                       │                    │
 │                        │                       ├─ extract() ───────→│ 抽取事实
 │ ← event: memory ───────┼───────────────────────┤ emit               │
 │ ← event: done ─────────┼───────────────────────┤                    │
 │                        │                       ├─ 解锁               │
 │                        │                       └─ 查收件箱→有则 drain │
```

### 1.2 分步说明

**① HTTP 层**（`src/server/http.ts` → `handleChatRoute`）

1. 读 body，取 `message` / `botId` / `model`（兼容 `text` / `agentId` 别名）
2. 空文本 → 400；缺 botId → 400
3. `runtime.isBusy(botId)` → 409（防止同一智能体并发回合）
4. 写 SSE 响应头，启动 15 秒心跳（`: ping\n\n` 注释行）
5. 挂 `response.on('close')` → abort 信号

**② 加锁与落库**（`AgentRuntime.runTurn`）

```ts
if (this.locks.has(agentId)) throw new AgentBusyError();
this.locks.add(agentId);
// ...
finally { this.locks.delete(agentId); }
```

用户消息**先落库再组装上下文**——这样 `ContextBuilder` 天然能看到这一轮。

**③ 压缩（可选）**

`Compactor.maybeCompact()` 的条件：

- 已有压缩覆盖点 `coversUpTo` 之前、且不在最近 `reserveRecent`（30）条之内的消息
- 数量 ≥ `compactionTrigger`（12）

满足则调 LLM 生成摘要，写入 `compaction/<agentId>.json`，然后**重新 buildAgent**（因为摘要变了）。

**④ 组装上下文**

见 §4 详细展开。

**⑤ 模型-工具循环**（`AgentLoop.run`）

- 每轮把 `built.messages` + 累积的对话发给模型
- 有工具调用 → 执行 → 结果落库 → 追加到对话 → 下一轮
- 无工具调用 → 结束，返回 `final_answer`
- 超过 `maxIterations`（12）→ 返回 `max_iterations`

**⑥ 记忆抽取**

回合结束后，取最近 12 条消息（含工具交互）作为「交换记录」，让模型判断哪些值得长期保留。返回值按作用域/层级写入，重复的自动合并。

### 1.3 关键代码位置

| 步骤 | 文件 |
| --- | --- |
| 路由与 SSE | `src/server/http.ts` `handleChatRoute()` |
| 回合编排 | `src/server/runtime.ts` `runTurn()` |
| 上下文组装 | `src/context/builder.ts` `ContextBuilder.build()` |
| 模型循环 | `src/agent/agent-loop.ts` `AgentLoop.run()` |

## 2. 群聊链路（扇出）

### 2.1 核心原则

> **群是成员表 + 广播**。没有中心 AI，没有群记忆。
> `@` 是**强信号**，不是投递开关——全体成员都会进入这一轮，各自决定说不说。

### 2.2 三波扇出

扇出不是简单的 `for member of members`。按《调整建议》1.1 与 2.1 落地后，分三波：

| 波次 | 谁 | 执行方式 | 为什么 |
| --- | --- | --- | --- |
| **1** | 被用户点名的人 | **串行** | 被点名者必须开口；后跑的人要能看到前面说了什么 |
| **2** | 在场但未被点名的人 | **并行** | 他们只是顺带看一眼，互相看不见是可接受的（见下方说明） |
| **3** | 被同事发言再次 `@` 的人 | **串行** | 二次叫醒，同样要保证顺序语义 |

```
前端              HTTP           AgentRuntime                     成员
 │                 │                  │                            │
 ├─ POST /rooms/:id/messages ────────→│                            │
 │                 │                  ├─ membersOf(roomId)         │
 │                 │                  ├─ resolveMentions(text)     │
 │                 │                  ├─ append(用户消息到时间线)   │
 │ ← room: room_message ──────────────┤ emit                       │
 │                 │                  ├─ 并行写入各成员的对话线 ───→│ (带 roomId/speaker)
 │                 │                  │                            │
 │                 │                  ├─ new SummonQueue(初始点名) │
 │                 │                  │                            │
 │                 │       ┌──────────┴──────────┐                 │
 │                 │       │  波次 1：被点名者     │                 │
 │                 │       │  for … await         │ ← 串行          │
 │ ← round_start ──┼───────┤  runRoomTurn ───────┼────────────────→│ 独立回合
 │ ← round_end ────┼───────┤  发言回流 + summonFrom│                │
 │                 │       └──────────┬──────────┘                 │
 │                 │                  │                            │
 │                 │       ┌──────────┴──────────┐                 │
 │                 │       │  波次 2：在场未点名   │                 │
 │                 │       │  Promise.all         │ ← 并行          │
 │                 │       └──────────┬──────────┘                 │
 │                 │                  │                            │
 │                 │       ┌──────────┴──────────┐                 │
 │                 │       │  波次 3：二次召唤     │                 │
 │                 │       │  while (hasWaiting)  │ ← 串行          │
 │                 │       └──────────┬──────────┘                 │
 │ ← fanout_done ──┼──────────────────┤ emit(spoke/silent 计数)     │
 │ ← done ─────────┼──────────────────┤                            │
```

**波次 2 的可见性说明**：同一波次并行跑的人**互相看不见**对方这一轮说了什么。
但他们能看到波次 1 的发言（通过简报里的「这一轮已经有人说过」），
以及自己对话历史里此前所有群消息。这是拿「同波次互不可见」换并行速度的取舍。

### 2.3 二次叫醒（成员 `@` 成员）

用户能 `@` 人，成员在自己的发言里 `@` 同事也一样要能把人叫起来。

```
成员 A 发言："…这个要 @测试运维 确认下"
        │
        ▼
resolveMentions(发言内容, 成员表)     ← 每条发言都重新解析
        │
        ├─ 命中的人还没跑过 → 排进等待队列，跑到他时 brief 变成「必须开口」
        └─ 命中的人已经跑过 → 同样入队，他会再跑一轮（如果没到上限）
```

**防环**：`ROOM_MAX_RUNS_PER_MEMBER = 2`

- 同一个成员在一轮 `roundId` 内最多被叫醒 2 次
- A `@` B → B 再跑一轮；B `@` 回 A → A 最多再跑一次，到顶后忽略
- 已经在队列里等待的人不重复入队

**一个易踩的坑**：并行波次派发时，必须**同步**先给每个成员占名额（`queue.reserve`），
否则同波次的人互相 `@` 时，会因为「对方还没登记」而漏掉二次叫醒。

### 2.4 分步说明

**① 点名解析**（`room/mentions.ts`）

```ts
resolveMentions(text, members)
// → { ids: string[], everyone: boolean }
```

实现细节：

- **长名优先**排序，且**匹配过的片段会被吃掉**——否则 `@知识库服务·备份` 会同时命中「知识库服务·备份」和「知识库服务」
- `@everyone` 支持别名：`everyone` / `all` / `所有人` / `全体` / `全员` / `大家`
- **解析失败当普通文本**，不报错

**② 入站消息的两次落地**

| 落地位置 | 目的 |
| --- | --- |
| 房间时间线（`rooms/<id>.jsonl`） | 用户能看到的群消息 |
| **每个成员自己的对话线**（`messages/<agentId>.jsonl`） | 成员的「同一条对话线」记忆 |

第二条是关键：对成员来说，**私聊和群聊是一条对话线**，用 `roomId` / `roomName` / `speaker` 标记来源。这样它下次私聊时仍然记得群里讨论过什么。

**③ 每个成员一个独立回合**

`runRoomTurn()` 为每个成员：

1. 拼装**回合纪律简报**（`buildRoomBrief`）
2. 决定工具集：**被点名时不给 `stay_silent`**（硬约束）
3. 调用 `runTurn()`，但用 `skipPersist: true`（入站消息已经写过了）
4. 收集 `posts`（`say` 工具往 `room.posts` 里塞的内容）

**④ 发言归属**

```ts
// 被点名：模型直接输出的文本也算发言（兜底）
if (posts.length === 0 && summoned) {
  const fallback = result.content.trim();
  if (fallback) posts.push(fallback);
}
```

**⑤ 发言回流**

每条发言要写**两处**：

- 房间时间线 → 用户和其他成员看得到
- **其他每个成员**的对话线 → 它们下一轮能接上话

### 2.5 沉默的处理

沉默（`status: 'silent'`）是**一等公民结果**：

- 不写房间时间线
- 前端只在消息流下方显示一行轻提示「XX 看过，没开口」，不进正文
- `RoundOutcome.note` 记录原因（如「这一轮没有要补充的」），仅用于解释

### 2.6 成员表变更

拉人 / 踢人 = 改 `room.memberIds`：

- **从下一回合生效**——新成员不回溯进群前的记录（时间线是全房间共享的，但它自己的对话线里没有历史）
- 上限 6（`ROOM_MEMBER_LIMIT`）
- 至少留 1 个，不能删空

## 3. 智能体 1:1 传话链路

### 3.1 核心原则

> **不等返回值**。发出去这一步就结束；对方的回复是之后的一个新回合。

### 3.2 时序

```
智能体 A 的回合            收件箱              智能体 B
     │                       │                    │
     ├─ send_to_agent({to:B})│                    │
     │   └ 校验 depth < 3     │                    │
     │   └ 校验 B 存在         │                    │
     ├─ enqueue() ──────────→│ (priority? 插队首)  │
     │ ← "已投递" ────────────┤                    │
     ├─ 回合继续 / 结束        │                    │
     │                       │                    │
     │                       │  ← B 回合结束后检查收件箱
     │                       ├─ count() > 0        │
     │                       ├─ drain() ──────────→│ 积压消息合并成一条
     │                       │                    ├─ buildAgentBrief(depth)
     │                       │                    ├─ runTurn()
     │                       │                    │  └ 可再 send_to_agent
     │                       │                    │
     │                       │  ← 新回合结束，再查收件箱（递归，受 depth 约束）
```

### 3.3 关键实现

**投递即返回**（`agent/inbox.ts`）

```ts
async enqueue(item): Promise<InboxItem> {
  const list = await this.load(item.toAgentId);
  if (item.priority) list.unshift(full);   // 紧急插队首
  else list.push(full);
  await this.save(item.toAgentId, list);
  return full;                              // 不等待对方处理
}
```

**批量消费**

```ts
async drain(agentId): Promise<InboxItem[]> {
  const list = await this.load(agentId);
  if (list.length === 0) return [];
  this.cache.set(agentId, []);              // 原子清空
  await rm(this.file(agentId), { force: true });
  return list;                              // 同一批一起交给模型
}
```

**自动触发**（`runTurn` 的 finally）

```ts
finally {
  this.locks.delete(agentId);
  const pending = await this.inbox.count(agentId);
  if (pending > 0) this.drainInbox(agentId).catch(() => undefined);
}
```

**防无限互发**

- `depth` 每传一次 +1，上限 3（`DEFAULT_MAX_AGENT_DEPTH`）
- 到顶后 `send_to_agent` 抛出错误：「传话链已达上限，请直接把结论说给用户」

### 3.4 区分三对「说话对象」

| 场景 | 怎么说话 | 谁能看到 |
| --- | --- | --- |
| 回主人（私聊） | 直接输出文本 | 只有主人 |
| 在群里对所有人说 | `say` 工具 | 房间时间线 |
| 对某个同事说 | `send_to_agent` | 用户也能看到这次传话 |

**设计约束**：群回合里如果要跟主人说一句群里不该听到的话，应该走私聊通道，不走群。

## 4. 上下文组装链路（ContextBuilder）

这是整套系统最核心的一段。

### 4.1 输入与输出

```ts
build(agent: Agent, task: Message, options?: { turnBrief?: string })
  → {
      system: string,          // 七段拼成的系统提示
      messages: LLMMessage[],  // 最近原文 + 当前任务
      stats: ContextStats,     // 每段用量，供前端展示
      surfaced: MemoryRef[],   // 本轮进过眼前的记忆，用于回写
      droppedRecent: number,
      droppedGroups: number,
    }
```

### 4.2 组装步骤

```
① 取候选
   recentCandidates = messages.recent(agentId, recentLimit=30, exclude=task.id)

② 分层挑选（各层按配额）
   ownPortrait     = portrait ∩ scope=self        (12 条配额)
   sharedPortrait  = portrait ∩ scope=user        (12 条配额)
   projectPortrait = portrait ∩ scope=project     (12 条配额)
   logRecent       = log                          (8 条配额)
   scratchRecent   = scratch                      (6 条配额)
   ※ 同层内排序：self 优先 > project > user，再按 updatedAt 倒序

③ 检索补齐（眼前没有但和任务相关的）
   retrieval = rankMemories(refs - inViewIds, taskText, { maxItems: 10, minScore: 0.06 })

④ 提取工作文件
   collectWorkingFiles(recentCandidates)   ← 从 tool_calls 的 path 参数提取，取最近 12 个

⑤ 估算各段需求 → 分配预算 → 截断
   allocateSections(budget, wants)

⑥ 裁剪最近原文（按原子组）
   trimRecentGroups(recentCandidates, alloc.recent)

⑦ 拼装 system + messages
```

### 4.3 系统提示的七段结构

```markdown
<Agent instructions>

<本轮规则简报>                      ← 群回合才有

## 画像
- 只有它知道的细节

## 关于你（所有智能体共用）
- 名字、时区这类

## 日志近况
- 最近发生的事（只带配额内）

## 随手笔记
- 临时备忘

## 相关检索
- 眼前没有但和当前任务相关的

## 更早的对话摘要
（已压缩 N 条更早的消息）
<摘要正文>

## 工作文件
- path/to/file.ts（read_file）
```

### 4.4 原子组裁剪（重要）

**问题**:按 token 从后往前切，会把 `tool_calls` 切掉只留 `tool` 结果 → 400。

**解法**（`groupMessages()`）:

```ts
// 把消息序列切成原子组
// 一条 tool_calls + 它引发的全部 tool_result = 一组
// 找不到父亲的孤立 tool_result 直接丢弃
```

裁剪时以**组**为单位从后往前保留，要么整组留下要么整组丢弃。

### 4.5 检索打分公式

```ts
score = 词面命中率
      × 层级权重      // portrait 1.2 / log 1.0 / scratch 0.85
      × 作用域权重    // self 1.1 / user 1.0 / project 0.95
      × 新鲜度        // 0.7 + 0.3 × (1 / (1 + age天/21))
```

词面命中率 = 命中词数 ÷ √(条目词数)。分词规则：拉丁词按 `[a-z0-9]{2,}`，中文按**相邻二字 bigram**。

### 4.6 surfaced 回写

`build()` 返回的 `surfaced` 列表会被 `touchSurfaced()` 写回：

```ts
entry.lastSurfacedAt = now;
entry.hits += 1;
```

用于老化统计——长期没被用到的条目自然沉底。

## 5. 记忆链路

### 5.1 写入链路（两条入口）

**入口 A：工具调用（显式）**

```
模型调用 remember({ text, scope, tier, tags })
  → 解析 scope → 决定 ownerId
      self    → context.agentId
      user    → 'user'
      project → context.projectIds[0] ?? agentId
  → MemoryStore.write()
      ├─ 过期清理
      ├─ 去重判定（三级）
      │   ├─ 命中 → 合并 / 覆盖（user 作用域总是覆盖）
      │   └─ 未命中 → 新建
      ├─ 容量 enforcement（降级 / 淘汰）
      └─ 落盘
  → 返回 "已记下（共用记忆/portrait）"
```

**入口 B：回合后自动抽取**

```
回合结束
  → 取最近 12 条消息作为「交换记录」
  → 短于 60 字符 → 跳过
  → LLM 抽取（要求返回 JSON 数组，含 scope/tier/tags）
  → 逐条 write()，自动合并重复
  → emit('memory', { added, merged })
```

**为什么两条都要**:

- 工具是**用户明确要求**「记住这个」时走的路径，可信度高
- 自动抽取是**兜底**，捕捉用户没说「记住」但明显值得留的信息

### 5.2 去重链路

```
judgeDuplicate(candidate, existing)
  │
  ├─ ① 数字守卫
  │     两侧数字集合都有值且不完全相同 → 判为两件事（reason: digits-conflict）
  │
  ├─ ② 归一化指纹完全一致 → 重复（reason: exact）
  │     归一化 = 去标点 + 全角转半角 + 小写
  │
  ├─ ③ Jaccard 相似度 ≥ 0.86 → 重复（reason: similar）
  │
  └─ ④ 实词覆盖率 ≥ 0.75 → 重复（reason: content）
        实词 = 去掉虚词表（我/你/的/了/是/叫/说…）后的 token
```

**冲突处理**:

- `user` 作用域命中重复 → **覆盖**为新文本（更新的覆盖旧的）
- 其他作用域 → 合并（保留原文，取更严的层级，累加 tags）

### 5.3 老化链路

```
每次 write() 都会触发 enforce()：

  对 portrait / log / scratch 三层分别检查：
    bucket = 该层全部条目按 updatedAt 升序
    overflow = bucket.length - policy.keep

  if overflow > 0:
      policy.overflow === 'demote' → 最旧的 overflow 条 tier 改为 'log'（画像→日志）
      policy.overflow === 'evict'  → 直接删除最旧的 overflow 条

  最后统一清理过期条目（scratch 超过 24h）
```

### 5.4 读取链路

见 §4。核心是**分层取用**：

| 层 | 读法 |
| --- | --- |
| 画像 | 按配额全部带上（3 个作用域各 12 条） |
| 日志 | 只带最近 8 条 |
| 随手 | 只带最近 6 条 |
| 其余 | 靠检索（`recall` 工具或自动补齐） |

**检索工具的额外价值**:`recall` 让智能体能主动翻旧账——「我之前是不是记过这个？」

### 5.5 压缩链路

```
maybeCompact(agent, provider)
  │
  ├─ olderThan(agentId, reserveRecent=30, coveredUpTo)
  │     = 全部消息 - 最近 30 条 - 已压缩覆盖范围
  │
  ├─ older.length < compactionTrigger(12) → 返回 null（不压）
  │
  ├─ 拼 transcript（最多 48000 字符）
  │     已有摘要 → 「已有摘要：… \n\n 新增历史消息：…」
  │     否则     → 「历史消息：…」
  │
  ├─ LLM 生成摘要（≤ 600 字，条目式，第三人称）
  │
  └─ 写 CompactionState { summary, coversUpTo=最后一条的时间戳, messageCount, updatedAt }
```

**压缩后的效果**:下次 `build()` 时，「更早的对话摘要」段会带上这段摘要，而不是逐条消息。

## 6. 工具调用链路

### 6.1 一次工具调用的完整过程

```
模型返回 tool_calls
  │
  ├─ 区分持久化 vs ephemeral
  │    ephemeral（say / stay_silent）→ 不落历史
  │    其余 → 落一条 assistant/tool_calls 消息
  │
  ├─ 逐个执行
  │    ├─ registry.execute(call, ctx)
  │    │    ├─ 工具不存在 → 返回 "Error: unknown tool ...（含可用列表）"
  │    │    ├─ 参数非法 JSON → 返回 "Error: arguments ... not valid JSON"
  │    │    ├─ 缺必填参数 → 返回 "Error: missing required argument(s): ..."
  │    │    ├─ 执行抛错 → 返回 "Error: tool ... failed: ..."（不抛出）
  │    │    └─ 正常 → 返回结果字符串
  │    │
  │    └─ 非 ephemeral → 落一条 tool/tool_result 消息（含 callId / durationMs / ok）
  │
  └─ 把结果追加到对话，进入下一轮
```

### 6.2 错误处理设计

**工具失败不抛异常，而是作为结果回给模型**——让模型有机会自我纠正：

```
→ calculator({"expression": "1+"})
← Error: tool "calculator" failed: expression did not evaluate to a finite number

（模型看到后重新调用正确的表达式）
```

**参数校验顺序**:JSON 解析 → 对象类型检查 → 必填项检查 → 执行。

### 6.3 ephemeral 工具

标记了 `ephemeral: true` 的工具调用**不落对话历史**：

- 理由：群里的 `say` 每次调用都落历史会产生大量噪音；而 `say` 的内容已经作为房间消息存下来了
- 实现：`registry.isEphemeral(name)` 判定，落库前过滤

## 7. SSE 事件流协议

### 7.1 事件类型总表

| 事件名 | 出现场景 | 载荷 |
| --- | --- | --- |
| `: ping` | 每 15 秒 | 注释行，保持连接 |
| `event:` | 私聊 + 群聊 | `AgentEvent`（见下） |
| `room:` | **仅群聊** | `RoomEvent`（见下） |
| `done:` | 全部 | 最终结果 |
| `error:` | 全部 | `{ message, status? }` |

### 7.2 AgentEvent

```ts
| { type: 'context';    stats: ContextStats }        // 上下文分层用量
| { type: 'message';    message: Message }           // 任何一条消息落库
| { type: 'iteration';  index: number }              // 进入第 N 轮模型调用
| { type: 'compacted';  coversUpTo; messageCount }   // 触发了压缩
| { type: 'memory';     added: MemoryRef[]; merged } // 写入了记忆
| { type: 'final';      content: string }            // 最终答复
```

### 7.3 RoomEvent

```ts
| { type: 'room_message'; message: RoomMessage }              // 房间时间线新增
| { type: 'round_start';  roundId; agentId; agentName }       // 某成员进入回合
| { type: 'round_end';    outcome: RoundOutcome }             // 某成员回合结束
| { type: 'fanout_done';  roundId; spoke; silent }            // 本轮扇出完成
```

### 7.4 分帧格式

```
event: event
data: {"type":"message","message":{...}}

event: room
data: {"type":"round_end","outcome":{...}}

event: done
data: {"content":"...","iterations":2,"stopReason":"final_answer"}
```

前端按 `\n\n` 分帧，逐行解析 `event:` / `data:` 前缀。

## 8. 前端消费链路

### 8.1 事件 → 界面（私聊）

```
applyEvent(messages, event)   // web/src/App.tsx
  │
  ├─ type !== 'message' → 忽略
  │
  ├─ role === 'user'
  │    └─ 用服务端 id 替换本地乐观添加的 pending- 占位（避免重复）
  │
  ├─ role === 'assistant' + content.type === 'text'
  │    └─ 新增一条助手消息
  │
  ├─ role === 'assistant' + content.type === 'tool_calls'
  │    └─ 挂到最近一条助手消息的 toolCalls（状态 running）
  │
  └─ role === 'tool' + content.type === 'tool_result'
       └─ 按 callId 回填 result / durationMs / status
```

**工具卡片的状态流转**:`running`（转圈）→ `ok`（✓）或 `error`（!）。

### 8.2 事件 → 界面（群聊）

```ts
onMessage      → 追加到消息流（含用户自己的回显替换）
onRoundStart   → 显示「XX 正在看这一轮…」
onRoundEnd     → 若 status !== 'spoke'，记录一条沉默提示
onFanoutDone   → 清除 in-flight 状态
```

### 8.3 滚动行为

```ts
// 只有用户明确向上滚才脱离跟随
onWheel: deltaY < -2 → stickToBottom = false
onScroll: 距底 < 24px → stickToBottom = true

// 自动贴底：内容变化时若仍在跟随，滚到底，并在下一帧补一次
```

**注意**:滚动容器必须有 `min-height: 0`，否则 flex 子项会被内容撑开，`overflow-y: auto` 永远不触发。

## 10. 排查手册

| 现象 | 可能原因 | 检查点 |
| --- | --- | --- |
| 发消息完全没反应 | 事件格式不匹配 / 后端未连 | 前端 `applyEvent` 是否处理 `type === 'message'`；`.offline` 提示 |
| 400 报错 | 裁剪破坏了 tool_calls 与结果的配对 | `groupMessages()` 是否按原子组裁剪 |
| 消息框滚不动 | 滚动容器缺 `min-height: 0` | `.chat-scroll-viewport` 计算样式 |
| 被点名却不说话 | 模型没调 `say` 且兜底逻辑没生效 | `runRoomTurn` 里 `summoned` 分支 |
| 群里所有人都回话 | 未被点名者也能调 `say` 之外的方式发言 | 检查是否给了 `stay_silent` |
| 记忆重复膨胀 | 去重判定过宽 | `judgeDuplicate()` 的数字守卫与阈值 |
| 长名被短名抢走 | 点名解析没「吃掉」已匹配片段 | `resolveMentions()` 的 `working` 变量 |
| 智能体互发停不下来 | 传话链深度未生效 | `agentChainDepth` 与 `maxAgentChainDepth` |
| 切频道崩溃 | `activeChannel` 为空时未兜底 | `App.tsx` 的 `activeChannel` useMemo |
| 群建不出来 | 后端返回裸 Room 缺 members | `roomView()` 包装 |
